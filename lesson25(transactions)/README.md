# Урок 25 — Транзакции

Шпаргалка для лайв-кодинга. Полная теория, тайминг и практика — в `Urok_24_Tranzakcii.md`.

## Главные аналогии (сказать в начале)
- Транзакция — **«всё или ничего»**. Обмен ключами от квартиры на деньги: либо оба действия происходят, либо ни одного. «Ключи отдал, денег не получил» недопустимо.
- Классика: списали деньги с одного счёта, и тут сервер упал. Деньги исчезли из мира. Транзакция гарантирует: либо оба обновления, либо ни одного.
- `defer tx.Rollback()` сразу после `Begin` — **страховка**: если до `Commit` не дошли, всё откатится само. После успешного `Commit` откат ничего не делает.
- `FOR UPDATE` — **табличка «занято»** на строке: пока мы работаем со счётом, остальные ждут своей очереди.

## Подготовка (до урока)
1. PostgreSQL запущен (см. `lesson23(sql-intro)/README.md`), база `coursedb`, пароль `secret`.
2. Создать таблицы счетов и начальные данные — файл `reset.sql` (счета Али 1000, Вера 500, Тимур 250):
   ```bash
   psql -h localhost -U postgres -d coursedb -f reset.sql
   # или в Docker:
   docker exec -i pg psql -U postgres -d coursedb < reset.sql
   ```
   Если хотите показать создание таблиц вживую — выполните вместо этого шаг 1 (`01-tablicy-schetov/schema.sql`) в `psql` по частям.
3. `go.mod` с драйвером `lib/pq` уже лежит в папке урока.

**Важно:** после шага 2 («деньги пропали») выполните `reset.sql` снова, иначе дальше суммы не сойдутся. В каждом шаге печатается строка «Всего денег в системе» — она должна быть **1750.00** всегда, кроме шага 2.

```bash
cd "lesson25(transactions)"

# или из папки шага: cd 04-polnyi-perevod && go run main.go
```

Шаги 4, 5 и 6 переносят деньги между счетами (общая сумма не меняется), а сами назад не возвращаются — перед повторным запуском выполните `reset.sql`. ## Частые ошибки новичков
| Ошибка | Симптом | Решение |
|---|---|---|
| Забыт `Commit` | Данные не сохранились | Вызывать в конце |
| Забыт `Rollback` | Транзакция висит, блокировки | `defer tx.Rollback()` сразу после `Begin` |
| Запрос через `db` в транзакции | Откат не работает | Только через `tx` |
| Нет `FOR UPDATE` | Потерянные обновления | Блокировать строки или обновлять атомарно |
| Долгая транзакция | Все ждут | Держать короткой, без HTTP-запросов внутри |
| Разный порядок блокировок | `deadlock detected` | Единый порядок (по возрастанию id) |
| `UPDATE` без проверки `RowsAffected` | Деньги «пропали» у несуществующего получателя | Проверять, что строк > 0 |
