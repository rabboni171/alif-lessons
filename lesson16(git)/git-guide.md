# Git — основы и ежедневная работа

Гайд для живой демонстрации: берём обычную папку с проектом (в которой ещё нет `.git`) и доводим её до рабочего репозитория на GitHub. Дальше — команды, которыми пользуемся каждый день.

---

## 0. Проверяем, что Git установлен

```bash
git --version
```

Если версия вывелась — всё готово. Если команда не найдена, значит установка не завершена (это студенты уже сделали заранее).

---

## 1. Знакомим Git с собой (делается один раз на компьютере)

Git подписывает каждый коммит именем и почтой автора. Это не аккаунт GitHub, а просто подпись — можно указать что угодно.

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "your@email.com"
```

Проверить, что сохранилось:

```bash
git config --global --list
```

> Это разовая настройка. Повторять для каждого нового проекта не нужно.

---

## 2. Заходим в папку проекта

У нас уже есть папка с кодом, но `.git` в ней нет — Git её пока не отслеживает.

```bash
cd путь/до/проекта
ls -la
```

Обратите внимание на `ls -la` — папки `.git` в списке нет. Это и означает, что Git здесь ещё не инициализирован.

---

## 3. Инициализация репозитория

```bash
git init
```

Что произошло: Git создал скрытую папку `.git` внутри проекта — именно там хранится вся история изменений. Проверим:

```bash
ls -la
```

Теперь `.git` появился.

```bash
git status
```

Git покажет список файлов проекта как **untracked** (неотслеживаемые) — он их видит, но пока не сохраняет в историю.

---

## 3.1. Как откатить `git init`, если сделали это случайно

`git init` не трогает и не изменяет файлы проекта — он только создаёт скрытую папку `.git`, в которой хранится вся история и настройки репозитория. Значит, чтобы полностью отменить `git init`, достаточно удалить именно эту папку.

**macOS / Linux:**

```bash
rm -rf .git
```

**Windows (PowerShell):**

```powershell
Remove-Item -Recurse -Force .git
```

Проверяем, что отменилось:

```bash
git status
```

Должна появиться ошибка `fatal: not a git repository (or any of the parent directories): .git` — значит папка снова «чистая», как будто `git init` никогда не запускали, и можно повторить демонстрацию с самого начала.

> Удаляется только папка `.git` (история, коммиты, ветки, подключённый remote). Сам код проекта, `.gitignore` и остальные файлы остаются на месте нетронутыми — команда безопасна именно потому, что удаляет строго `.git`, а не всю папку проекта.

---

## 4. Файл `.gitignore` — что НЕ отправлять в Git

Не все файлы проекта нужно сохранять в истории: скомпилированные бинарники, логи, локальные настройки IDE.

Создаём файл `.gitignore` в корне проекта:

```
# бинарники Go
*.exe
*.out

# папка сборки
/bin/

# файлы окружения
.env

# системные и IDE-файлы
.DS_Store
.idea/
.vscode/
```

> Если файл уже случайно попал под отслеживание Git до того, как вы добавили его в `.gitignore`, одного `.gitignore` недостаточно — надо ещё явно убрать файл командой `git rm --cached имя_файла`.

---

## 5. Добавляем файлы в индекс (staging area)

```bash
git add .
```

`git add` не сохраняет изменения навсегда — он только помечает файлы как «готовые к коммиту» (это называется staging area, промежуточная зона).

Проверяем, что попало в индекс:

```bash
git status
```

Файлы, которые ещё зелёные (added) — готовы к коммиту.

---

## 6. Первый коммит

Коммит — это «снимок» состояния проекта с сообщением, что изменилось.

```bash
git commit -m "Первый коммит: начальная структура проекта"
```

Смотрим историю:

```bash
git log
```

Компактный вариант:

```bash
git log --oneline
```

---

## 7. Подключаем репозиторий на GitHub

Репозиторий на GitHub уже создан заранее (пустой, без README). Копируем его HTTPS-ссылку из GitHub (кнопка **Code → HTTPS**).

```bash
git remote add origin https://github.com/имя-пользователя/название-репозитория.git
```

Проверить, что ссылка подключилась:

```bash
git remote -v
```

Переименовываем текущую ветку в `main` (стандарт для GitHub):

```bash
git branch -M main
```

---

## 8. Первый пуш (отправка) на GitHub

```bash
git push -u origin main
```

Флаг `-u` (`--set-upstream`) связывает локальную ветку `main` с веткой `main` на GitHub — после этого достаточно писать просто `git push` без указания origin и ветки.

> При первом пуше GitHub попросит авторизоваться. Пароль от аккаунта GitHub напрямую больше не подходит — нужен **Personal Access Token** (создаётся в настройках GitHub: Settings → Developer settings → Personal access tokens) либо SSH-ключ. Это стоит настроить заранее до занятия, чтобы не тратить время в кадре.

Обновляем страницу репозитория на GitHub — файлы должны появиться.

---

## 9. Ежедневный цикл работы с Git

Как только репозиторий подключён, дальнейшая работа — это повторение одного и того же цикла:

```bash
git status              # что изменилось
git add .                # добавить изменения в индекс
git commit -m "текст"    # зафиксировать изменения
git push                 # отправить на GitHub
```

### Смотреть, что именно изменилось

```bash
git diff
```

Показывает построчные изменения в файлах, которые ещё не добавлены в индекс.

### Забрать изменения с GitHub (например, если работали на другом компьютере)

```bash
git pull
```

### История коммитов

```bash
git log --oneline
```

---

## 10. Шпаргалка (cheat sheet)

| Команда | Что делает |
|---|---|
| `git init` | Создать репозиторий в текущей папке |
| `git status` | Показать состояние файлов |
| `git add .` | Добавить все изменения в индекс |
| `git add имя_файла` | Добавить конкретный файл |
| `git commit -m "текст"` | Сохранить снимок изменений |
| `git push` | Отправить коммиты на GitHub |
| `git pull` | Забрать изменения с GitHub |
| `git log --oneline` | Краткая история коммитов |
| `git diff` | Показать построчные изменения |
| `git remote -v` | Показать подключённые удалённые репозитории |

---

## 11. Частые ошибки новичков

- **"fatal: not a git repository"** — вы не в той папке, либо забыли `git init`. Проверьте `pwd` и `ls -la` (ищите `.git`).
- **Забыли `git add` перед `git commit`** — коммит без добавления файлов в индекс сохранит пустой снимок (или не сохранит новые файлы вовсе).
- **`git push` без `-u` в первый раз** — Git попросит указать, куда именно пушить (`git push -u origin main` нужен только один раз).
- **Коммит с пустым `-m ""`** — Git откроет текстовый редактор в терминале, если сообщение не указано. Если это произошло случайно — выйти можно клавишей `Esc`, затем `:wq` и `Enter` (в редакторе Vim).
