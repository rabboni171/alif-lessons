# Горутины и WaitGroup: как выбрать нужную форму

## 1. Что вообще такое горутина

Обычный вызов функции Go выполняет по порядку — строка за строкой, дожидаясь, пока каждая функция закончится:

```go
someFunc() // program ждёт, пока someFunc отработает, и только потом идёт дальше
```

Если поставить перед вызовом слово `go`:

```go
go someFunc()
```

Go запускает функцию "в фоне" и сразу идёт дальше, не дожидаясь её завершения. Это и есть горутина.

Важно: если `main()` закончится раньше горутины — горутина исчезнет вместе со всей программой, даже не успев ничего напечатать. Поэтому одного `go` мало, нужен способ подождать — об этом в разделе 3.

## 2. Три формы записи `go ...`

### 2.1 `go someFunc(args)` — запуск обычной именованной функции

```go
func printHello(name string) {
	fmt.Println("Привет,", name)
}

func main() {
	go printHello("Аня")
}
```

Бери эту форму, когда:
- функция уже написана и у неё есть имя;
- код достаточно большой или его удобно вызвать и без `go` (например, для проверки).

### 2.2 `go func() { ... }()` — анонимная горутина без аргументов

```go
func main() {
	go func() {
		fmt.Println("Работаю в фоне")
	}()
}
```

Обрати внимание на `()` в самом конце — без них это просто объявление функции, которое никогда не запустится. `()` здесь означает "вызови прямо сейчас".

Бери эту форму, когда:
- код короткий и одноразовый — заводить для него отдельную именованную функцию избыточно;
- горутине не нужно "текущее" значение переменной цикла (если нужно — смотри 2.3).

### 2.3 `go func(id int) { ... }(i)` — анонимная горутина С аргументом

```go
func main() {
	for i := 1; i <= 3; i++ {
		go func(id int) {
			fmt.Println("Горутина №", id)
		}(i)
	}
}
```

Здесь два `i`: один снаружи — переменная цикла, второй — параметр `id` внутри самой горутины. Мы явно передаём `i` как аргумент в момент запуска.

Зачем так: пока горутина ждёт своей очереди на выполнение, переменная цикла `i` может успеть измениться. Передавая её аргументом, мы говорим Go: "запомни значение `i`, каким оно было именно сейчас — и используй именно его", а не то, каким `i` станет чуть позже.

Бери эту форму всегда, когда запускаешь горутины внутри цикла и внутри горутины нужен текущий номер, индекс или элемент.

### Шпаргалка

| Ситуация | Форма |
|---|---|
| Функция уже написана, есть имя | `go someFunc(args)` |
| Код короткий, одноразовый, вне цикла | `go func() { ... }()` |
| Горутина в цикле, нужно текущее значение переменной цикла | `go func(id int) { ... }(i)` |

## 3. sync.WaitGroup: как дождаться горутин

`WaitGroup` — это просто счётчик "сколько горутин ещё не закончили". Три метода:

- `wg.Add(1)` — "+1 к счётчику, жди ещё одну горутину";
- `wg.Done()` — "-1 от счётчика, я закончила" (вызывается изнутри горутины);
- `wg.Wait()` — "не идти дальше, пока счётчик не станет 0".

### Правило 1 — `Add` до `go`, а не после

```go
wg.Add(1)      // сначала: "жди ещё одну"
go work(&wg)   // потом запустили
```

Если сделать наоборот, main может дойти до `wg.Wait()` раньше, чем горутина вызовет `Add` — счётчик ещё 0, и `Wait()` никого не будет ждать.

### Правило 2 — `Done` через `defer`, первой строкой

```go
func work(wg *sync.WaitGroup) {
	defer wg.Done() // выполнится в любом случае, когда функция закончится
	// ... остальной код
}
```

`defer` гарантирует вызов `Done()`, даже если функция завершится раньше времени.

### Правило 3 — `WaitGroup` передаём указателем

```go
func work(wg *sync.WaitGroup) { ... } // *sync.WaitGroup, а не sync.WaitGroup
go work(&wg)
```

Без `&` горутина получит свою отдельную копию счётчика, и `main` никогда не узнает, что она закончилась — программа зависнет (`deadlock`).

### Пример: все три правила вместе

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func downloadFile(name string, wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Println("Начали:", name)
	time.Sleep(1 * time.Second)
	fmt.Println("Готово:", name)
}

func main() {
	var wg sync.WaitGroup
	files := []string{"a.zip", "b.zip", "c.zip"}

	for _, f := range files {
		wg.Add(1)
		go downloadFile(f, &wg)
	}

	wg.Wait()
	fmt.Println("Все файлы скачаны")
}
```

## 4. Как это применить к домашним задачам

Задания 1-3 — намеренно без горутин или со Sleep-костылём, чтобы почувствовать проблему до решения. WaitGroup здесь ещё не нужен.

Задания 4-6 — у тебя уже есть готовая именованная функция (`printSlowly`, `greet`, `countTo`) — используй форму 2.1: `go printSlowly(name, &wg)`.

Задания 7-9 — то же самое, но без отдельной функции, прямо внутри `main`. В задании 8 внутри `for i := 1; i <= 8; i++` горутине нужен текущий `i` — обязательно форма 2.3.

Задания 13-15 (гонка данных) — тоже цикл с горутинами, снова форма 2.3: каждой горутине важен собственный номер `i`, особенно в задании 15, где `results[i] = 1`.

Задания 16-20 (средний уровень) — везде один и тот же скелет: цикл по срезу → `wg.Add(1)` → `go func(i int) { ... }(i)` → внутри запись в `results[i]` → после цикла `wg.Wait()`. Если в цикле `for i, item := range slice` внутри горутины нужны и индекс, и сам элемент — передавай аргументами оба.

## 5. Мини-чеклист перед запуском

1. Перед каждым `go` стоит `wg.Add(1)`?
2. Внутри горутины первая строка — `defer wg.Done()`?
3. `WaitGroup` передан с `&` (указателем)?
4. Если горутина в цикле и ей нужен номер или элемент — он передан аргументом, а не взят "снаружи"?
5. В конце есть `wg.Wait()`?

Если на все пять пунктов ответ "да" — можно запускать.
