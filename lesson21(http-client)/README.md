# Урок 21 — HTTP-клиент

Шпаргалка для лайв-кодинга. Теория, тайминг, практика и ДЗ — в `Urok_20_HTTP_klient.md`.

## Главные аналогии (сказать в начале)
- HTTP-запрос — **письмо в организацию**. Ты пишешь: адрес (URL), тип обращения (метод), реквизиты (заголовки), содержание (тело). Тебе отвечают: резолюция (статус-код), свои реквизиты и содержание ответа.
- Браузер делает то же самое, когда вы открываете сайт. Сегодня пишем **свой мини-браузер, только без картинок**.
- `Body.Close()` — **закрыть за собой дверь**: иначе соединения копятся и программа упирается в лимит.
- Таймаут — **«жду ответа не дольше 5 секунд»**. Без него программа может ждать вечно.

## Правило статус-кодов
| Код | Смысл |
|---|---|
| 2xx | Успех (200 OK, 201 Created) |
| 4xx | **Виноват ты** (404 не найдено, 401 нет доступа, 429 слишком часто) |
| 5xx | **Виноват сервер** (500, 503) — можно повторить позже |

**Главная мысль урока:** 404 — это **не** ошибка Go. `err == nil`, запрос прошёл, сервер просто ответил «нет». Статус проверяем сами.

## Что сказать по ходу
- **Шаг 1:** «Почему `defer` после проверки `err`? Запрос не удался → `resp == nil` → паника».
- **Шаг 3:** `NewDecoder` читает из потока без лишнего `[]byte` — `Body` это `io.Reader`, как файл на уроке 15.
- **Шаг 5:** «`http.Get` без таймаута — мина. Сервер завис — вы висите вечно».
- **Шаг 6:** `http.Get` — быстрый способ, `NewRequest` + `Do` — полный контроль (заголовки, токен). Чтобы увидеть, что получил сервер, замените адрес на `https://httpbin.org/headers`.
- **Шаг 7:** ручная склейка строк ломается на пробелах и кириллице — показать вывод `Экранирование:`.
- **Шаг 9:** связываем с уроками про структуры и методы: `NewAPIClient` — конструктор, `Send` — метод. `Params` — «бланк запроса»: заполняем только нужные поля, остальные пустые. `Response` — это **указатель, куда положить ответ** (как `&u` в `Unmarshal`). `ctx` — первым параметром, как на уроке 19.
- **Шаг 10:** каждая горутина пишет в **свою** ячейку `results[idx]` — гонки нет, мьютекс не нужен. Запустить с `go run -race`.
- **Шаг 11:** `httpbin.org/status/503` всегда отвечает 503 — удобно показать все три попытки.

## Шаг 12: resty — что говорить
Сначала мы всё сделали сами на `net/http`, чтобы понимать, что происходит внутри. Теперь показываем, как то же самое делают в реальных проектах. Основной упор — на то, что **библиотека не меняет правила**: 404 по-прежнему не ошибка, статус проверяем сами.

| Что писали руками | Как в resty |
|---|---|
| `http.Client{Timeout: ...}` | `resty.New().SetTimeout(...)` |
| Общая часть адреса | `SetBaseURL(...)` |
| `url.Values` | `SetQueryParam(...)` |
| `fmt.Sprintf("/posts/%d", id)` | `SetPathParam("id", ...)` и `"/posts/{id}"` |
| `json.Marshal` + `bytes.NewBuffer` + `Content-Type` | `SetBody(структура)` |
| `json.NewDecoder(resp.Body).Decode(&x)` | `SetResult(&x)` |
| `resp.StatusCode >= 400` | `resp.IsError()` |
| `Authorization: Bearer ...` | `SetAuthToken(...)` |
| Цикл с `Sleep` из шага 11 | `SetRetryCount` + `AddRetryCondition` |

Что важно:
- В `main` вызовы идут по одному: можно закомментировать все, кроме нужного, и раскрывать по ходу. `client.SetDebug(true)` печатает запрос и ответ целиком — удобно для показа.
- Функция `failed` — те же две проверки, что мы делали раньше: `err` и статус.
- Retry в resty по умолчанию повторяет только при `err`, а 5xx — нет. Поэтому нужен `AddRetryCondition`.
- `Body.Close()` писать не нужно, resty закрывает тело сам.

## Шаг 13: как показывать
Безопасные случаи 2 и 3 запускаются сразу. Опасные закомментированы — раскомментируйте **один** и запустите:
1. забыт `Close` — 1000 запросов, дальше «too many open files»;
4. нет таймаута — программа висит несколько минут (прервать `Ctrl+C`);
5. `defer` до проверки `err` — паника. `go vet` эту ошибку ловит сам.

## Важно перед занятием
- **Лимит GitHub:** без токена 60 запросов в час **с одного IP**. Если вся группа сидит на одном Wi-Fi, лимит кончится быстро, и вместо данных придёт `403`. Код это переживёт (вернётся ошибка «GitHub вернул статус 403») — это тоже хороший повод поговорить про статус-коды. Лимит видно в заголовках `X-Ratelimit-Remaining` (шаг 6).
- Шаг 7 использует поиск GitHub — у него лимит ещё строже (10 запросов в минуту).
- **Если нет интернета:** урок целиком работает по сети, поэтому покажите заранее сохранённый вывод запусков.
- Публичные API для практики: `jsonplaceholder.typicode.com` (без лимитов), `api.github.com`, `httpbin.org`.

## Частые ошибки новичков
| Ошибка | Симптом | Решение |
|---|---|---|
| Забыт `Body.Close()` | `too many open files` | `defer` сразу после проверки `err` |
| `defer` до проверки `err` | nil pointer panic | Сначала `if err != nil`, потом `defer` |
| Нет таймаута | Программа висит | Свой `http.Client{Timeout: ...}` |
| Не проверен статус | Пустые данные без ошибки | Проверять `resp.StatusCode` |
| Тело читается дважды | Второй раз пусто | Прочитать один раз в переменную |
| Ручная склейка URL | Ломается на пробелах и кириллице | `url.Values` |
| Нет `Content-Type` | Сервер не понимает тело | `Header.Set("Content-Type", "application/json")` |
| Забыт `&` в `Decode(&todo)` | Ошибка или пустая структура | Передавать указатель |

## Фишка Go
Полноценный HTTP-клиент — в стандартной библиотеке, без единой внешней зависимости. Добавь горутины — и пять запросов выполняются за время одного. Ни промисов, ни `async/await`, ни колбэков: обычный последовательный код, просто запущенный параллельно.
